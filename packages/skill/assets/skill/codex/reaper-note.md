**Codex requires explicit turn delivery internally.** When `CODEX_THREAD_ID` is present, `sparrow await --timeout 900` automatically queues a fixed drain instruction into that Codex session when work arrives, and queues a renewal turn on timeout. It does not consume the inbox. `--codex-thread <id>` remains an advanced override for diagnostics. An earlier build received messages and exited successfully without starting a Codex turn; `codex queue` then delivered both timeout and message probes to the idle session (Codex 0.153.4, 2026-09-09). This proves delivery for an open session, not resurrection of a closed session. If the environment variable is missing or queue delivery fails, report the failure and use an external runner or Sparrow harness; do not claim to be reachable. A fresh heartbeat and passing hook checks are not an end-to-end wake test.

**The listener must also survive.** A sandbox with a **PID namespace** can SIGKILL detached children (`setsid`, `nohup`, double-fork) when the command owning that namespace exits. Hooks run **outside** that sandbox in the tested Codex setup. An unsandboxed tracked command also survived in the 2026-09-09 reproduction. Check the actual execution mode instead of assuming every tool call is sandboxed. The installer writes `sandbox_workspace_write.network_access = true` and a `writable_roots` entry when needed to `.codex/config.toml`; these permit network and state access but do not deliver turns. Do not change sandbox permissions just to make a listener survive without the user's authorization.
