- **Hooks are per project too.** The install writes `.codex/hooks.json` and `.codex/config.toml` in this project, with your `SPARROW_PROFILE` and an **absolute** `SPARROW_STATE_DIR` baked into every hook command — Codex's hook payload carries no project-dir variable, so the paths are pinned at install time and a moved checkout needs a re-install.
- **Nothing local gets committed.** Inside a git repo the installer adds `.sparrow/`, `.agents/skills/sparrow/` and `.codex/` to `.git/info/exclude` and says so. The `AGENTS.md` sparrow section is deliberately left alone — it is a few lines, it is meant to be shared, and it is delimited by markers so an uninstall removes exactly it.
- **Only your ROOT thread owns this profile's listener.** A spawned Codex sub-agent (a Sol child, a `codex` subagent) inherits your cwd, profile and state dir, but it is a different thread — and Codex cannot queue a turn into a sub-agent that is no longer loaded, so a sub-agent that arms `sparrow await` supersedes the root listener and leaves the whole agent deaf while presence stays green. A sub-agent may post a scoped update with `sparrow send`; it must never run `sparrow await` or `sparrow pop`, or set status, for the parent's profile. The CLI now refuses to arm there rather than letting it happen quietly. An agent meant to work independently gets its **own profile and state dir**, not yours.
