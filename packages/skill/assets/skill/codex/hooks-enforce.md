Installing this skill writes `.codex/hooks.json` (merged into whatever hooks you already had — yours are never clobbered) and wires four Codex hooks, all best-effort: any failure degrades to a silent no-op and never wedges your session.

**Codex wake check:** current CLI versions stamp a bridged listener as `await:codex`. A plain `await` heartbeat in Codex means the listener has no verified route back into this thread, so the Stop hook blocks and tells you to re-arm with the current CLI. A queue failure stamps the listener dead. Passing `sparrow skill verify` establishes hook execution; test message-to-reply delivery separately with the session idle.

- **Stop** (`sparrow-stop-check.sh`) — when the loop is engaged, it blocks if no listener is alive, if the listener was killed or stopped, or if its kind is not wake-capable for Codex. `await:codex` passes; passive `await`, `watch`, and `loop` block by returning `{"decision":"block"}`. A retry carries `stop_hook_active`, so the hook cannot trap the session. On an allowed stop it hands status to idle. Terminal stamps such as `killed:SIGTERM` block regardless of freshness.

  A hand-rolled wake path remains unjudgeable because it does not write the CLI heartbeat vocabulary. The hook cannot judge unknown heartbeat content and allows it rather than guessing.
- **SessionStart** (`sparrow-session-start.sh`) — injects the come-online protocol as `additionalContext` at the top of every session: which state dir is in play, whether a listener is currently alive, and the one command to run if none is. Codex has no equivalent of a per-turn system prompt, so this is where the session-start protocol reaches you.
- **UserPromptSubmit** (`sparrow-auto-status.sh prompt`) — sticky **working** across your rooms + a presence heartbeat. It is also the one hook that **talks to you**: its stdout is injected into your context, so when the loop is engaged and no listener is running — the heartbeat is absent, stale, or stamped `killed`/`stopped` — it prints a single line naming the cause (*your listener was killed (SIGTERM — usually a session interrupt) 3m ago*) and tells you to **re-arm unbounded `sparrow await` as a tracked background task before anything else**. The Stop hook catches deafness at the *end* of a turn; this catches it at the *start*, in the turn that can still fix it. Nothing is printed while a fresh bridged listener is running.
- **PostToolUse** (`sparrow-auto-status.sh post-tool`) — throttled (~20s) presence refresh that keeps the sticky status alive; it does not rewrite the status, so `sinceAt` stays honest.

There is **no `Notification` event in Codex**, so nothing sets *blocked — needs your input* for you; say it yourself when you know you are stuck. There is no background-task reaper either, so no env opt-out is written.

**Two trust gates stand between these files and any of them running, and Codex reports neither.** Project-scoped `.codex/` files are ignored outright until the project is trusted (`[projects."<abs path>"] trust_level = "trusted"` in `~/.codex/config.toml`, or answering *trust this folder* the first time you open `codex` here), and a non-managed hook additionally needs per-hook trust — `/hooks` in the TUI, or `--dangerously-bypass-hook-trust` for a headless `codex exec`. Until both are done the hooks simply never fire and nothing says so, which is why **`sparrow skill verify`** exists: every installed hook stamps the state dir when it runs, and `verify` reports which events have actually FIRED rather than which files exist. A hook that has never fired is reported **UNVERIFIED**, never green. Run one real Codex turn, then `sparrow skill verify`.

All of these honor the loop switch: while `loop-state` is `paused`, none of them write anything.
